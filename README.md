# 座椅养护台账 · BenchCare

公园与街道公共座椅的登记、报损、维修与复验闭环系统。纯 Python 标准库 + 原生前端，
SQLite 存储座椅状态，照片本地保存，定位服务使用可替换的模拟适配器。

## 一条命令启动

```bash
python3 run.py            # 首次自动播种演示数据（含重复报损案例）并打开浏览器
python3 run.py --reset    # 清空并重新播种
python3 run.py --port 8080 --no-browser
```

启动后访问 http://127.0.0.1:8000 。右上角可切换身份：**市民 / 维保一班 / 维保二班 / 复验员老周**。

## 业务闭环

```
市民报损 ──► 未结事件(归并重复报损) + 维修工单，座椅标记停用
     │
养护班组抢单认领（并发仅一组成功）
     │
按损坏类型布设封控（警示带/围挡，留存封控记录）
     │
维修前拍照 ──► 维修施工 + 登记材料消耗 ──► 维修后拍照，提交复验
     │
复验员复验（维修人本人禁止复验）
   ├─ 不通过 → 退回班组返工
   └─ 通过 → 核对警示带已撤除 + 维修后照片齐全 + 油漆已干燥 → 恢复可使用，归档
```

### 五类损坏的不同现场措施

| 类型 | 现场措施 | 封控方式 |
|---|---|---|
| 松动螺栓 | 局部围挡停用涉事座位，紧固/更换膨胀螺栓 | 局部警示带 |
| 木板断裂 | 整椅封控，清除毛刺碎板，换板打磨 | 整椅围挡 |
| 油漆未干 | 保留告示与隔离，静置至干燥方可开放 | 隔离绳+告示牌 |
| 座椅被搬动 | 复位原点位，核对基础孔位重新锚固 | 复位区域警示带 |
| 已拆除待重装 | 核查基础预埋件，重装到位并锚固 | 基础坑位盖板+警示带 |

## 关键规则

- **重复报损归并**：同一座椅、同一损坏类型、事件未结时，新报损自动并入（报损计数 +1，
  共用同一张工单）。不同损坏类型拒绝归并（HTTP 409）；事件归档后再报损生成新事件。
- **并发认领**：`UPDATE ... WHERE status='reported'` 条件更新原子抢占，两个班组同时接单
  只有一个成功，另一个收到冲突错误。
- **职责隔离**：非责任班组不能操作他人工单；维修人员（认领/完工者）不能复验自己的工单。
- **重新开放三核对**：警示带已撤除、维修后照片已上传、油漆已干燥，缺一不可。
  油漆有服务端干燥计时，未干时复验通过被阻断。
- **地图 ⇄ 工单互跳**：地图标注、座椅详情、工单编号、事件之间相互链接；移动端详情页
  顶部优先展示位置与安全状态横幅。
- **照片**：前端拍照后压缩（≤800px JPEG）上传，保存在 `data/photos/`，维修前后并排展示。

## 目录结构

```
run.py                 启动入口（播种 + HTTP 服务）
benchcare/
  db.py                SQLite 建表与连接
  models.py            材质图标 / 损坏类型 / 现场措施字典
  service.py           领域服务（报损归并、认领、封控、维修、复验、材料）
  server.py            标准库 HTTP（JSON API + 静态页 + 照片）
  seed.py              10 处座椅台账 + 重复报损等演示案例
  static/              index.html / styles.css / app.js（原生 SPA + SVG 地图）
data/                  运行时生成：benchcare.db、photos/
tests/test_service.py  领域规则测试
```

配色：公园白 `#f6f9f4`、深绿 `#1f5130`、维修橙 `#ef7d1e`。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

覆盖：并发认领只有一组成功、不同损坏类型错误归并被拒、维修人员复验自己被拒、
未干油漆复验阻断（推进时钟至干燥后放行）、警示带/照片复验门槛、返工重提、
拆除重装标记、材料消耗校验。
